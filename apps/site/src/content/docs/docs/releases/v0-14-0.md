Dusori v0.14.0 completes the path after research finds useful material. The Sources shelf is now
searchable without creating an index, the Reading room keeps adjacent evidence in reach, and a
selected passage can become a learner-owned note without losing its source context. This release
also includes the browser-storage and navigation recovery work completed after v0.13.0.

:::note[Superseded by v0.15.0]
[Download the current release](https://github.com/udhawan97/Dusori/releases/tag/v0.15.0).
:::

## Find the right source

Use **Find a saved source** to match a title, publisher, provider, author, original filename, or URL
host. The three shelf lenses keep their meanings narrow:

- **All** shows every active source in the topic.
- **Evidence** shows local text Dusori can read and quote.
- **References** shows saved URLs that still need readable text.

Search and filters are local, transient projections. They write no index, preference, dismissal,
progress, or completion state.

## Follow the reading trail

Opening a source now names the reading copy, its evidence state, its provider or publisher, and its
position in the active shelf. **Previous source** and **Next source** follow the existing manifest
order; they do not rank, reorder, or mark anything complete.

Select up to 1,200 characters and choose **Quote selection in a note**. Dusori explicitly creates an
ordinary Markdown note with the exact quote, nearest section heading, source path, and content
SHA-256 before opening the note editor. Choosing **Annotate in a study note** without a selection
creates a source-linked note without inventing a passage. A later source revision never silently
changes the preserved quote or learner commentary.

## Review additional research results

The varied first shelf remains automatic after an allowed run. Further ranked results stay in the
run until you choose **Approve and add** for one exact result. That action reuses only the already
allowed provider and refreshes the brief when readable evidence is available; it does not broaden
provider consent or create fallback egress.

## Browser recovery and navigation

Browser startup now honors the workspace's recorded IndexedDB or OPFS backend and fails closed when
that backend is unavailable. It never opens an apparently empty fallback while another store may
hold the learner's files. Research, Sources, Map representation, document paths, and topic creation
also share one URL/history decision path across reload, Back, and Forward.

## Privacy and compatibility

- Workspace schema remains version 1.
- Source search and reading navigation make no network request and persist no index.
- Annotation notes are user-owned Markdown; machine-owned source manifests are unchanged.
- The browser PWA, Node companion, macOS Apple silicon app, and Windows x64 app share this behavior.
- macOS and Windows installers are not Apple-notarized or Microsoft Authenticode-signed. Verify the
  official release checksums; in-app updater signatures are a separate trust mechanism.
