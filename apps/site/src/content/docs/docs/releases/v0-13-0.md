Released 2026-08-13.

v0.13.0 routes each question locally before consent, adds two narrow public-information sources,
keeps mobile permission actions reachable, and makes **System** appearance respond while the app is
open. The workspace format and question-to-brief trust contract remain compatible with v0.12.4.

:::note[Superseded by v0.14.0]
v0.14.0 keeps these provider boundaries and adds source-shelf search, the connected Reading room,
source-grounded annotation notes, and browser-storage recovery.
:::

## Route, permit, then search

1. Dusori classifies the question on the device using explicit, tested topic rules.
2. The consent sheet shows undecided providers relevant to that question.
3. The learner allows or declines each provider independently.
4. Research runs only the exact relevant-and-allowed intersection.

There is no fallback egress: allowing a specialist provider never lets it receive an unrelated
question. The full provider catalog and every saved decision remain visible outside the focused
prompt. Ambiguous words such as `virus`, `infection`, `archive`, `office`, `windows`, and `library`
do not route a specialist on their own.

## Two specialist sources

- **Europe PMC** is offered for narrow biomedical and life-science questions. Dusori makes one
  bounded search, saves a returned abstract as readable evidence, and otherwise keeps a citation
  reference. An abstract is not the full paper, and linked access rights still vary.
- **Library of Congress** is offered for narrow cultural-heritage questions. Dusori accepts only
  canonical digitized item records and saves catalog metadata as browser references, not copied
  media or page text. Request starts are limited to 20 per minute; valid `Retry-After` guidance
  creates local backoff without an automatic retry.

The provider catalog now contains 15 tested research adapters: 11 keyless browser adapters and four
companion adapters. Hugging Face is not included because this release has no concrete model- or
dataset-catalog workflow that would justify sending a query there.

## Consent and focus that hold up on small screens

- The provider list scrolls independently between a fixed heading and fixed action footer.
- All consent actions remain visible at 320 × 568 and under zoom, provider-growth, and shorter
  dynamic-viewport stress.
- Tab and Shift+Tab stay inside the modal.
- Escape, backdrop dismissal, **Decide later**, **Keep all off**, **Save choices**, and completion
  return focus to **Research topic**.
- No provider request is made before a saved allow decision.

## Live appearance and bounded failures

**System** now follows operating-system light/dark changes without a reload. Paper, Ink, and Night
remain stable explicit choices. Provider search and capture timeouts now abort the underlying fetch,
while one provider's failure still leaves every other provider's useful result intact. Duplicate
research results are filtered by canonical URL, DOI, and conservative scholarly-title matches, but
an abstract already returned by search wins over a duplicate reference. Each provider's own
`found`, `empty`, or `failed` outcome remains in the durable run trail.

## Desktop support and trust

- macOS 12 or newer on Apple silicon only
- Windows x64
- Browser/PWA and Node.js 24 companion
- Signed GitHub updater artifacts with separate check, download, install, and relaunch actions

The Mac and Windows installers are open-source builds but are not Apple-notarized or Microsoft
code-signed. Gatekeeper or SmartScreen may warn on first launch; compare the installer with
`SHA256SUMS.txt` from the release. The updater signature is a separate trust mechanism.

:::caution[One-time repair for v0.12.0 and v0.12.1]
Those two desktop versions open to a launch-time 404, so Settings is inaccessible. Install the
current v0.14.0 release manually once. The workspace is stored separately and remains in place.
Normal in-app updates work from v0.12.2 onward.
:::
