Released July 27, 2026. Version 0.6.0 widens what Dusori can read and what you can steer, without moving anything off your device. Every addition here keeps the same promise as the rest of the product: your Markdown stays yours, nothing is replaced without you accepting a diff, and nothing leaves the device without a disclosure naming exactly where it goes.

[Open Dusori](https://udhawan97.github.io/Dusori/app/) · [View the GitHub release](https://github.com/udhawan97/Dusori/releases/tag/v0.6.0)

## Tags you already write

Dusori now reads tags out of your own Markdown — a `tags:` list in frontmatter or an inline `#tag` in the body, exactly as Obsidian understands them. A vault you edit elsewhere keeps the same tags, because nothing new is stored: tags are read from the files each time you search or open the graph.

- Search accepts `tag:name`, on its own or alongside words, and shows the tags it found on each result.
- The graph filters by tag, and the artifact finder matches them too.
- Insights counts your tag vocabulary.

A Markdown heading is still a heading, `#123` is still an issue number, `page#section` is still a URL fragment, and anything inside backticks or a code fence is still code. None of them become tags.

## PDFs as sources

Choose a `.pdf` in the source library and Dusori reads its text on your device. The file is never uploaded, and the reader itself is only fetched the first time you import one, so the offline app shell does not grow for sessions that never touch a PDF.

The extracted text becomes an ordinary local source — hashed, recorded in the topic manifest, appended to the update log — so search, the graph, briefs, and review prompts all use it like anything else.

A scanned PDF has no text layer to read. Dusori says exactly that instead of saving an empty source, and points you at the manual routes. There is no OCR.

## Learning preferences you can edit

Each topic's `TUTOR.md` has always described how you want that topic taught. Now you can edit it without leaving Dusori: set the depth, then add, remove, or reorder preferences.

Nothing is written until you accept a diff, through the same protocol your notes and roadmap already use. If you changed the file in another editor first, your version stays put and Dusori writes a sibling proposal instead. Only the depth line and the preference bullets are rewritten — prose, extra frontmatter, or a heading you added stays exactly as you wrote it.

With the companion running, an AI provider configured, and a consent of its own, a model can propose preferences from the change you describe. It receives the topic title, the current preferences, and your request — no note, no source, no other file. Its answer is re-read and re-rendered onto your file, so it can change the depth and the bullets and nothing else, and an answer Dusori cannot use changes nothing at all. You still see a diff naming the model before anything is saved.

## More places evidence comes from

Two more providers your browser reaches on its own, no key and no companion:

- **OpenAlex** for scholarly work. Abstracts are rebuilt on your device from the inverted index publishers license, so a citation becomes readable text without fetching the paper.
- **npm registry** for packages, capturing the published readme.

And one through the companion:

- **Reddit.** Reddit no longer answers anonymous clients, so this needs a free Reddit app of your own. Create a "script" app at [reddit.com/prefs/apps](https://www.reddit.com/prefs/apps) and set `REDDIT_CLIENT_ID` and `REDDIT_CLIENT_SECRET` before launching the companion. The credential stays in the companion process. Without it the provider simply reports that it is not configured and the run skips it. Posts marked over 18 are left out; a self post is captured as its own text, and a link post as an honest reference.

## Sharper review sessions

Review sessions gained two prompt kinds, still fully deterministic:

- A **cloze** hides the longest word of a source's own opening sentence. Nothing is invented — the excerpt still shows the answer when you ask for it.
- A **locate** prompt asks which of your sources covers a section, and appears once a topic has a second source to tell apart.

Sessions still run three to five prompts, open with explain and close with compare, and name a source title, section, and workspace path on every prompt.

## Smaller things

- **Export this topic** writes one topic's files as a portable ZIP. It is a copy to keep or read elsewhere, not a workspace archive Dusori can import back, and both the button and a note inside the archive say so.
- Insights reports what the review queue is holding: overdue, due today, how many topics carry a schedule at all, and a bounded histogram of what falls due next. Derived on read, like everything else there.
- Workspace health can create the page an unresolved wikilink already names, at the exact name the link uses, so the link resolves afterwards. It only ever adds a file that does not exist yet.

## Fixed

- The preview server had no MIME type for `.mjs`, so a bundled worker was served as `application/octet-stream` and browsers refused to run it. PDF import could not have worked from a local build before this.
