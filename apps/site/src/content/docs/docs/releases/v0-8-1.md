Released August 1, 2026. Version 0.8.1 tightens the path from a new topic to evidence and from evidence to recall. Short phone screens keep the next action visible, failed provider runs say they failed, and every user-requested workspace view starts at its own heading.

[Open Dusori](https://udhawan97.github.io/Dusori/app/) · [View the GitHub release](https://github.com/udhawan97/Dusori/releases/tag/v0.8.1)

## Review without hunting for the next step

Source-grounded review keeps **Back** and **Next** in the pinned decision area. The prompt, answer, and revealed source can still scroll when they need room, but the controls that advance the session no longer sit below an unmarked inner fold at 320×720 or 375×812.

The final rating remains explicit. Opening, navigating, revealing, or abandoning a session still writes no review schedule; only **Got it** or **Needs work** on the last prompt changes `review.json`.

## Tell failure from an empty result

Research now distinguishes four outcomes: results, partial provider failure, a completed search with no candidates, and a run where every allowed provider failed. An all-provider failure names that state, says that no suggestions were returned or saved, and offers **Retry scan**. “No new suggestions matched” appears only when at least one provider completed.

Consent and approval boundaries are unchanged: a provider is never contacted before its disclosure is accepted, and no result becomes a local source before approval.

## Start each view in the right place

Today, Research, roadmap, graph, insights, local documents, and the new-topic form now reset inherited document scroll on a user-requested transition and move keyboard focus to the destination heading. The new view therefore starts below the sticky canvas bar instead of inheriting an unrelated position from the previous screen.

Research also compresses its mobile introduction into a three-part Discover / Compare / Capture legend. The first provider consent control stays in the opening viewport at 320×720 and 375×812 while the approval-first explanation remains visible.

## Continue directly from Today

This release includes the post-v0.8.0 improvements already merged to `main`:

- Set a topic to Active, Paused, or Complete from its own Today card.
- Follow a local `[[wikilink]]` from a Dusori document using the same resolution rules as the knowledge graph.
- Distinguish “no sources yet” from saved sources that have no readable text on this device.

These controls keep the same deterministic, local-file-backed behavior as their existing owning workflows. Viewing a card or following a link does not change progress.

## Install the matching companion

Dusori remains fully useful in the browser without the companion. For loopback-only page capture and optional local research providers, use the version that matches this release:

```bash
npx @udhawan97/dusori@0.8.1
```

The companion requires Node.js 24 LTS, binds only to `127.0.0.1`, and stops when its terminal closes. Publication is performed by the exact-tag workflow after the GitHub release is published.

### Safety and portability

- No account, telemetry, hosted application backend, graph database, paid service, plugin, or AI model is required.
- Workspace state remains portable Markdown and JSON; network and AI egress remain separately consent-gated.
- Existing Markdown is never silently overwritten, and review state changes only after an explicit final rating.

### Known limitations

- Direct folder access requires a supported Chromium browser; other browsers use ZIP portability.
- A physical touch device, Safari, and Firefox are not part of this release's automated browser matrix.
- Remote provider availability remains outside Dusori's control; a failed run is now recoverable and truthfully labelled.
