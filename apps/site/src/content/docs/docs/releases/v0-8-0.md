Released July 30, 2026. Version 0.8.0 turns Today into a workspace-wide decision surface grounded in the files Dusori can actually inspect. It also makes conflict proposals durable across reload, import, and export without deleting either Markdown version.

[Open Dusori](https://udhawan97.github.io/Dusori/app/) · [View the GitHub release](https://github.com/udhawan97/Dusori/releases/tag/v0.8.0)

## Continue from evidence

**Continue learning** excludes completed topics and keeps deterministic ordering: due spaced reviews first, then active topics before paused topics, with the least recently updated item first.

The action comes from current local evidence:

- A due topic with an approved readable source starts a source-grounded review.
- An unfinished objective without approved readable text opens Research.
- Another source-ready objective opens its roadmap and may offer an optional first review.
- A paused topic opens without silently resuming it.

Opening any item changes no progress. A URL-only reference does not make a topic source-ready, and Dusori makes no claim about source quality or understanding.

## Attend only to what is real

**Needs attention** contains conditions proven by the current workspace. Pending edit proposals and invalid or missing source records take priority; unresolved wikilinks remain secondary hygiene. Each item routes to the existing proposal review or Workspace health flow, where the evidence and any bounded repair remain visible.

There are no invented reminders, dismiss-only cards, mastery claims, or new background schedules.

## Keep proposal decisions across reloads

When a tracked Markdown file changed outside Dusori, the external version remains active and the Dusori change becomes a dated sibling proposal. Version 0.8.0 records that lifecycle in a schema-versioned, hash-guarded `Topics/<slug>/proposals.json` ledger.

The ledger stores the target and proposal paths plus a `pending`, `accepted`, or `kept` resolution. Today can therefore recover the exact pending diff after a reload. Accepting the proposal or keeping the current document resolves the attention item while preserving both Markdown files. Historical `.proposed-*` files that predate the ledger remain readable history and are never guessed to be pending.

The ledger is validated with the rest of the workspace and travels through whole-workspace export and import.

## Install the matching companion

Dusori remains fully useful in the browser without the companion. For loopback-only page capture and optional local research providers, use the version that matches this release:

```bash
npx @udhawan97/dusori@0.8.0
```

The companion still requires Node.js 24 LTS, binds only to `127.0.0.1`, and stops when its terminal closes.
